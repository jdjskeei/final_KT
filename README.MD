# Ответы

## Задание 1

Это один и тот же процесс, просто у него разные PID. В контейнере web-42 он имеет PID 1, а на хосте PID 48231. Так происходит из-за PID namespace, который позволяет изолировать процессы.

При этом systemd всё равно может управлять этим процессом через cgroups. То есть процесс может быть внутри контейнера и одновременно контролироваться системой на хосте.

## Задание 2

Потому что контейнеры используют одно ядро Linux и системное время у них общее с хостом.

Если разрешить контейнеру менять время, это может повлиять на всю систему и другие контейнеры. Например, могут неправильно работать таймеры, сертификаты и задачи по расписанию.

Поэтому Docker по умолчанию не выдаёт контейнерам CAP_SYS_TIME, даже если внутри используется root.

## Задание 3

Контейнер будет использовать сеть хоста, потому что мы не создали отдельный network namespace.

То есть у него будут те же IP-адреса, интерфейсы и порты. Если nginx на хосте слушает порт 80, то через ss -tlnp внутри контейнера тоже можно увидеть этот порт, хотя информация о самом процессе может быть недоступна.

В Docker обычно создаётся отдельный network namespace, а здесь мы изолировали только процессы и hostname.

## Задание 4

Docker, systemd и Kubernetes выполняют разные задачи, но используют одни и те же механизмы ядра Linux.

Например, cgroups нужны для управления ресурсами процессов, а namespaces для их изоляции.

Docker использует их для контейнеров, systemd для управления сервисами, а Kubernetes управляет контейнерами через container runtime.

То есть это разные инструменты, которые работают поверх общих возможностей ядра Linux.
